# Dependency Management

## Purpose

One tool (UV), one manifest (`pyproject.toml`), one lockfile (`uv.lock`).
No `setup.py`, no `requirements*.txt`, no `poetry.lock`. Every generated
project uses the same dependency-declaration layout so `make dev-setup`
works identically across projects.

## Pattern

- **UV** manages virtualenvs, installs, and lock resolution. The generated
  `Makefile` hard-wires `PYTHON := uv run python` and
  `PYTEST := uv run pytest`.
- **`pyproject.toml`** is the only source of truth. It contains:
  - `[project]` — metadata + runtime dependencies
  - `[dependency-groups]` — test / lint / docs groups (installed via
    `uv sync --all-groups`)
  - `[build-system]` — setuptools backend with `src/` layout
  - Tool configs (`[tool.ruff]`, `[tool.pytest.ini_options]`) colocated.
- **Pinning**: lower-bound pins (`>=`) for libraries that follow semver
  reliably; exact pins for pre-1.0 tooling (UV, ruff). Current pins live
  in [`LIBRARIES.md`](LIBRARIES.md), refreshed by
  `/developer-plugin:refresh-libraries`.
- **`uv.lock`** is checked in. Regenerated by `uv lock` whenever
  `pyproject.toml` changes.

## Key APIs

- `uv sync --all-groups` — install runtime + dev deps from lock.
- `uv lock --upgrade` — refresh lock after bumping pins in
  `pyproject.toml`.
- `uv run <cmd>` — invoke a tool inside the managed env without
  activation.
- `uv add <pkg>` — append a new dependency + re-lock in one step.

## Illustrative snippet

```toml
[project]
name = "{project_name}"
version = "0.1.0"
description = "{project_description}"
requires-python = ">=3.11,<3.14"
dependencies = [
    "pyspark[pipelines]>=4.1.1",
    "delta-spark>=4.3.0",
    "spark-expectations>=2.10.0",
    "duckdb>=1.5.2",
]

[dependency-groups]
dev = [
    "pytest>=9.0.3",
    "pytest-mock>=3.15.1",
    "ruff>=0.15.11",
]

[build-system]
requires = ["setuptools>=61.0"]
build-backend = "setuptools.build_meta"

[tool.setuptools.packages.find]
where = ["src"]

[tool.ruff]
line-length = 100
target-version = "py311"

[tool.ruff.lint]
select = ["E", "F", "I", "N", "W", "UP"]

[tool.pytest.ini_options]
testpaths = ["tests"]
addopts = "-v --tb=short"
markers = [
    "integration: tests that run against real source data",
]
```

## Common pitfalls

- Mixing `pip install` with `uv sync` — diverges the lock. Use UV
  exclusively.
- Forgetting the `pyspark[pipelines]` extra — plain `pyspark` omits the
  Spark Declarative Pipelines CLI (`dp`).
- Using the Scala 2.12 Delta jar (`delta-spark_2.12`) — PySpark 4.x ships
  Scala 2.13; always use `delta-spark_2.13` Maven coordinates.
- Unpinned major versions — a silent `pytest` 8 → 9 jump can drop
  deprecated fixtures mid-CI. Let `refresh-libraries` surface majors for
  explicit acknowledgement.
