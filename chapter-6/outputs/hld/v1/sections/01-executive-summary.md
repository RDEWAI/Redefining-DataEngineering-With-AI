## 1. Executive Summary

The Patient 360 pipeline consolidates 13 Synthea healthcare source tables (13.5M total rows verified, 636 MB raw) into a unified patient view serving 415+ clinical, billing, and administrative users across five role groups. The architecture uses a Medallion pattern (Bronze, Silver, Gold) implemented with **Spark Declarative Pipelines** (SDP, Apache Spark 4.1+) for intra-pipeline orchestration and **Apache Airflow** for cross-pipeline scheduling and dependency management. Bronze ingestion is **config-driven**: 13 per-table YAML configuration files define source connection, schema, CDC method, load priority, and DQ rule references -- eliminating per-table boilerplate code. Silver and Gold transformations remain code-driven using SDP decorators (`@dp.table`, `@dp.materialized_view`). Delta Lake provides ACID guarantees and SCD Type 2 tracking on patient dimensions. All tables use hourly batch ingestion via Full Snapshot CDC, satisfying the DRD's 1-hour clinical latency SLA [DRD SS4.4] and 2-second query response target [DRD SS4.3] while keeping implementation within the team's demonstrated proficiency in batch Spark pipelines and Delta Lake MERGE INTO [team-capabilities.md SS2]. Data quality uses a dual-layer strategy: SDP built-in `@dp.expect*` decorators for inline schema and null checks, with Spark Expectations YAML rules (generated from the DQS) for complex business rules and cross-table validations. Pipeline observability combines OpenLineage/Marquez for lineage tracking and Grafana for pipeline metrics dashboards.
