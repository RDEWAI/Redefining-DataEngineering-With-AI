## Key Schema Decisions

### 1. Gold Layer: Two-Tier Design (User Decision)
- Star schema foundation (dim_patient, dim_provider, dim_organization, dim_payer, fact_encounter, fact_condition, fact_medication)
- Plus 3 consumer aggregate tables (patient_summary, patient_clinical_history, patient_billing_summary)
- Rationale: Star schema for ad-hoc flexibility; consumer tables for DRD-mandated access patterns

### 2. SCD Strategy: Governance Mixed Approach (User Decision)
- dim_patient: Type 2 for address, city, state, county, zip, marital_status
- dim_patient: Type 1 for first_name, last_name, birth_date, death_date, gender, race, ethnicity
- dim_provider, dim_organization, dim_payer: Type 1 only (no versioning)
- Per governance policy defaults; deviates from HLD blanket Type 2

### 3. NULL Marital Status: Pass Through (User Decision)
- NULL marital_status preserved as-is (not defaulted to UNKNOWN)
- 31.6% NULL rate (primarily minors)

### 4. Bronze Type Preservation
- Source types preserved (not cast to VARCHAR)
- Schema enforcement at Bronze using explicit StructType
