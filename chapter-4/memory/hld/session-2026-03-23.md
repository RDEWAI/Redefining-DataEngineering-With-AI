## Changes Made

### Change 1: Config-Driven Bronze Ingestion

- Added per-table YAML config files (13 files for Phase 1) driving a generic ingestion engine
- Config scope: Bronze only -- Silver/Gold transformations remain code-driven
- Config content: Extended (table name, source path, schema reference, CDC method, frequency, partition column, write mode, DQ rule reference, load priority, SCD type, hash columns, derived fields, target layer mapping)
- Config file structure: One YAML file per source table (not monolithic)
- Config validation: Dual gate -- static JSON Schema at pre-commit + runtime fail-fast at startup
- DQ rules NOT duplicated in ingestion config -- already config-driven via SE YAML from DQS

### Change 2: Spark Declarative Pipelines (SDP) Adoption

- Upgraded processing engine to Apache Spark 4.1+ for SDP support
- SDP provides intra-pipeline dependency resolution, parallelism, incremental processing
- Apache Airflow added as cross-pipeline orchestrator (Bronze -> Silver -> Gold)
- Layer mapping:
  - Bronze: `@dp.table` (streaming tables) -- generated dynamically from config
  - Silver: `@dp.table` -- code-driven SCD2 and transformations
  - Gold: `@dp.materialized_view` -- incremental refresh from Silver changes
- Airflow tasks call `spark-pipelines run --spec <layer>.yaml`
- Team is Familiar with SDP [team-capabilities.md SS2] -- upskilling needed in sprint 1

### Change 3: Dual DQ Strategy (SDP + Spark Expectations)

- SDP `@dp.expect*` decorators for inline schema/null/range checks
- Spark Expectations YAML rules for complex business rules, FK checks, aggregate validations
- Clear responsibility split documented in SS6.3
- No DQ duplication between ingestion config and SE YAML files

## Design Decisions Made

1. **Config scope**: Bronze only -- Silver/Gold remain code-driven (business logic not suitable for declarative config)
2. **Config structure**: Per-table files (not monolithic) for independent reviewability and selective deployment
3. **Config content**: Extended -- 14 fields per config covering everything the generic ingestion engine needs
4. **Config validation**: Dual gate (static + runtime) for comprehensive error catching
5. **SDP adoption**: Built into Spark 4.1+, team Familiar, provides dependency resolution + parallelism + incremental processing
6. **Orchestration split**: Airflow for cross-pipeline scheduling, SDP for intra-pipeline orchestration
7. **DQ strategy**: SDP expectations for inline checks, SE for complex rules -- clear boundary documented in SS6.3
