## Key DQ Design Decisions (User-Confirmed)

1. **FK Orphan Handling**: Reject + Quarantine -- aligns with STM Edge Cases sheet (DQ-021, DQ-022) and HIPAA audit requirements. Orphan records written to quarantine table with full logging.

2. **Statistical Distribution Thresholds**: Hybrid approach -- +/-2% for patient-critical tables (patients, encounters, allergies), +/-5% enterprise defaults for all others. Balances patient safety with operational noise reduction.

3. **Allergy Escalation Path**: Elevated -- PagerDuty to on-call engineer AND Clinical Ops Director (clin-ops@hospital.org), 10-minute response target. Reflects zero-missed-allergy DRD requirement (SS1.3) and PHI Safety Critical classification (SS7.2).

4. **Alert channels**: PagerDuty + Slack #data-alerts for CRITICAL, Slack #data-quality for WARNING, email digest for INFO.

5. **Multi-environment enforcement**: DEV=5% log-only, QA=1% halt-on-critical, PROD=0.1% full enforcement (per dq-standards.md SS4).

6. **Check frequency**: Per pipeline run for CRITICAL/WARNING field-level and reconciliation; daily for statistical null rates; every 15 min for clinical freshness SLA.

7. **Reconciliation tolerances**: Per SLA definitions -- 0% source-to-bronze, +/-0.1% patient/encounter gold, +/-1% conditions, +/-0.01% financial sums.

8. **Freshness scope**: All three layers (bronze, silver, gold) -- not gold-only. Bronze/Silver freshness provides early pipeline health warning.
