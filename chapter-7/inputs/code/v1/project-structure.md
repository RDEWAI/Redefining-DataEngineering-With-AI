# Project Structure

## Purpose

Every generated project uses the same top-level directory tree so engineers
moving between projects find the same files in the same places. The tree
encodes the Medallion architecture (Bronze → Silver → Gold) at the source
level, separates pipeline entry-points from reusable library code, and keeps
all infra manifests (Docker, configs) at the root.

## Pattern

```
{project_root}/
├── src/{project_name}/          # Library code — importable package
│   ├── bronze/                  # Ingest modules (schemas, CSV/API readers, factory)
│   ├── silver/                  # Dim + fact transforms (scd2.py, dims.py, facts.py)
│   ├── gold/                    # Consumer-layer aggregates
│   └── utils/                   # Cross-layer helpers (spark.py, delta.py, logging.py)
├── pipelines/                   # Spark Declarative Pipelines entry-points
│   ├── bronze_pipeline.py       #   @dp.table functions — one per raw source
│   ├── silver_pipeline.py       #   @dp.materialized_view for dims, @dp.table for facts
│   └── gold_pipeline.py         #   @dp.materialized_view for consumer datasets
├── tests/
│   ├── conftest.py              # Session-scoped SparkSession + DeltaCatalog fixture
│   ├── test_bronze/
│   ├── test_silver/
│   └── test_gold/
├── expectations/                # Declarative DQ rule files (JSON/YAML, one per table)
│   ├── bronze/
│   ├── silver/
│   └── gold/
├── scripts/                     # Operational helpers (uc_init.py, gen_delta_load.py, ...)
├── etc/conf/                    # UC server + service configs (bind-mounted into Docker)
├── warehouse/                   # Local Delta store (gitignored)
├── data/raw/                    # Sample input files (gitignored in prod; seed in dev)
├── airflow/                     # Optional — DAGs + per-table YAML configs for Airflow mode
│   ├── dags/
│   └── configs/
├── _infra/ci/                   # CI workflows (GitHub Actions / GitLab CI)
├── docker-compose.yml           # UC OSS + Marquez + Postgres stack
├── spark-pipeline.yml           # Spark Declarative Pipelines manifest
├── Makefile
├── pyproject.toml
├── uv.lock
├── run_local.py                 # Single-layer local runner (--layer bronze|silver|gold|all)
├── README.md
└── CLAUDE.md                    # Project-scoped Claude instructions
```

## Key rules

1. **`src/{project_name}/` is importable** — every subdir has `__init__.py`.
   Pipeline entry-points in `pipelines/` import from `src/`, never the
   reverse.
2. **`pipelines/` is Spark-runtime-only** — functions decorated with
   `@dp.table` or `@dp.materialized_view`. No helpers.
3. **`scripts/` is for one-off CLI tools** — UC bootstrap, delta-load
   generators, verification utilities. Executed via
   `uv run python scripts/<name>.py`, not imported.
4. **`expectations/` mirrors the layer split** — one subfolder per layer,
   one rule file per table.
5. **Tests mirror `src/`** — `tests/test_{layer}/test_{module}.py`
   matches `src/{project}/{layer}/{module}.py` one-for-one.
6. **Root files are fixed** — `Makefile`, `pyproject.toml`,
   `docker-compose.yml`, `spark-pipeline.yml`, `run_local.py` always live
   at the root.

## Generated by

`create-scaffold` renders this tree from a cookiecutter template.
`update-scaffold` patches missing directories when the LLD adds a new
layer or when this pattern doc changes.

## Common pitfalls

- Nesting pipelines inside `src/` — keeps import graph confused and
  breaks `@dp.table` discovery by the SDP CLI.
- Putting runtime helpers (e.g., `spark.py`) in `scripts/` — they are
  imported by `src/` modules and must live in `src/{project}/utils/`.
- Forgetting `__init__.py` in a new subpackage — breaks `uv run pytest`
  discovery and causes SDP glob imports to silently skip files.
- Writing directly under `warehouse/` from app code — writes go through
  `utils/delta.save_as_delta_table()`, which also registers the table in
  Unity Catalog.
